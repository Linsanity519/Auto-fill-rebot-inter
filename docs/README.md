## 界面方案

`界面方案/` 下是三套 GUI 方案的视觉稿和方向 C 的技术选型，不是页面抓取记录。

## 怎么抓

### 先跑抓取器，别一开始就手动翻 DOM

```bash
python tools\capture.py --out docs\XX-配置项抓取.md
```

一次 dump 出字段全表、控件类型（推断）、必填、**同名 label 计数**、当前不可见的字段。
另外两个模式：

```bash
python tools\capture.py --options "生效平台"        # 把某个下拉点开读全选项
python tools\capture.py --snap a                    # 存快照
#   （人工在页面上把「生效渠道」切成「定向」）
python tools\capture.py --snap b --diff a           # 出联动差异
```

`--diff` 是最值钱的：它直接给出「选了这个值之后哪些字段出现 / 消失 / 变必填」，
而这决定 **Excel 模板出哪些列** —— 模板列在跑之前就定死，漏一条整个模板要重做。

⚠ **它出的是草稿不是结论**：控件类型是推断的（多选下拉 vs 勾选框组务必人眼确认），
远程搜索的下拉读回来是空（正常，得打字才拉数据）。核对完再把草稿里那段 ⚠ 删掉。

### 手动抓（抓取器覆盖不到的部分）

程序自带的调试浏览器就够用，不用另外开工具：

```python
from src import chrome
from src.paths import app_dir
chrome.launch("http://127.0.0.1:9222", app_dir() / ".chrome-profile", "要抓的页面URL")
# 人工在弹出的窗口里登录（扫码），然后：
from src.browser import Browser
with Browser("http://127.0.0.1:9222", 30000) as b:
    p = b.page      # 标准 Playwright Page，随便点随便读
```

抓的时候注意记这几样，这几样最容易想当然（前两条抓取器已经替你数了）：

1. **label 原文**（页面上写的是「我想投放」不是「人群标签」）
2. **同名 label 出现几次**、哪一个是要填的那个（人群那一段一个 label 出现 5 次）
3. **选项全集**（虚拟列表要滚到底，或者用搜索逐个确认）
4. **选了某个值之后才冒出来的字段**（在期大会员 → 必填的天数区间）
5. **控件真实类型**（多选下拉 ≠ 勾选框组，填法完全不同）

## 定位回归（离线，抓后台改版）

抓完页面、调好 yaml 选择器之后，顺手在 `tests/fixtures/<配置类型>/` 存一份
**真实页面快照**（`outerHTML` + 一个 `.expect.json`，格式见 `tests/fixtures/README.md`）。
`python tools\test_filler_locate.py` 会 headless（不连内网、不登录）跑一遍
「yaml 里的定位目标还在不在」—— 后台改版把某个 label / 结构动了，这里会红，
提醒你重抓快照并同步改 yaml。没装 playwright 的 Chromium 二进制时整体 skip，不挡 CI。

⚠ 只测「定位得到几个元素」，测不了「下拉选项对不对 / 联动」—— 那还是只有实跑能验。
