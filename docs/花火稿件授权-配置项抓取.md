# 花火稿件授权 — 配置项抓取

抓取时间：2026-09-23　抓取方式：CDP 连已登录 Chrome，dump 弹窗 outerHTML + 打接口核对
页面：`https://ad.bilibili.co/#/assets/index?activeTab=authorization&type=list&subTab=video_auth`
路径：资产 → 账号及视频授权 → **花火内容授权** → 「+ 添加稿件授权」

前端栈：**iView**（`ivu-*`）。业务组件自己的语义类名（`search-type-select` /
`video-auto-complete` / `bind-time-type` / `bind-auth-range` / `form-footer`）稳定可用，
**没有编译哈希类名**。弹窗根节点 `.ivu-modal-content`，标题 `添加稿件授权`。

---

## 一、弹窗里的字段全表

| 顺序 | label（页面原文） | 控件 | 定位 | 选项全集 / 默认值 |
|---|---|---|---|---|
| 1 | 视频（必填） | 下拉 + 输入框，同一行 | `.search-type-select` / `.video-auto-complete input.ivu-input` | 下拉：**视频链接**（默认） / 稿件avid / 稿件bvid |
| 2 | 授权时间 | 单选按钮组 | `.bind-time-type` | **不限**（默认） / 30天 / 60天 / 90天 / 自定义 |
| 3 | 共享范围 | 单选按钮组 | `.bind-auth-range` | **同客户&同品牌&同代理**（默认） / 同客户&同品牌 / 仅本账号 |
| 4 | 我已阅读并同意《商业合作授权协议》 | 勾选框 | `.form-footer input[type=checkbox]` | **默认不勾** |
| — | 取消 / 确定 | 按钮 | `.form-footer .buttons button` | — |

弹窗顶部还有一条 alert：「7日内对同一视频仅有 3 次申请机会，已使用（0/3）次」。

### 坑（都是实测踩到的）

1. **类型下拉默认是「视频链接」，每次开弹窗都要切成「稿件bvid」。**
   不切的话 bvid 当链接校验，直接不过。
2. **先切类型、再填 bvid。** 反过来切类型会把输入框清空。
3. **敲完 bvid 必须点一下浮层里那条候选，光敲进去不算填上。**（最贵的一条）
   输入框是远程 auto-complete：敲字 → 打一次校验接口（转圈图标
   `.ivu-input-icon-validate.ivu-load-loop`）→ 弹出一条候选（封面 + 标题 + UP主 UID）。
   **不点这条候选**的话，表单的值是空的，输入框标红「请输入需要绑定的bilibili视频」，
   点「确定」没有任何反应。
   ⚠ 浮层被 iView 的 transfer 挪到了 **body 底下**：`.video-ac-dropdown li.ivu-select-item.auto-complete-option`，
   在 `.ivu-modal-content` 里怎么找都找不到，会误判成「没有候选」。
   ⚠ 浮层开着的时候，**下一次点击会被它吃掉**（那一下只是关浮层）——
   表现是「点了 30天 没选上」「协议勾不上」，还不报错。选中候选会顺带关掉浮层。
4. **协议不勾时点「确定」毫无反应，也不报错。** 成功判据只能看弹窗有没有关掉。
   勾选要点那个画出来的方框 `.form-footer .ivu-checkbox`，**不能点外层 label** ——
   label 里连着《商业合作授权协议》那个 target=_blank 的链接，点中文字会开一个新标签页，
   勾选状态一点没变。
5. **提交成功后还有第二层弹窗**：「添加视频授权 / 发送绑定申请成功 / …请到花火平台确认」+
   【我知道了】，带一层盖住整页的遮罩。不点掉，下一条连「添加稿件授权」都点不动
   （点击全落在遮罩上、不报错，表现是整批从第 2 条起卡住）。
   ⚠ 它的标题是「添加**视频**授权」，和填表弹窗「添加**稿件**授权」不是一个词，
   按标题找弹窗的代码要分清。
6. **成功判据要看「成功弹窗冒出来」，不能看「填表弹窗关掉了」。**
   这两件事不同时发生：成功弹窗盖上来时填表弹窗有时还开着，按后者判会把
   **已经发出去的**报成失败（2026-09-23 实测 BV1Mqeq6GE3E 报失败、接口回查
   auth_times 已经是 1）。这种误报最贵 —— 重跑一次就白烧掉 3 次机会里的一次。
7. 单选组的选中态在 `label.ivu-radio-wrapper` 上加 `ivu-radio-wrapper-checked`，
   点完要回读核对。默认值本来就对时别白点一下。

## 二、校验接口（预检就靠它）

```
GET /platform/api/web_api/v6/resource/sanlian/commercial_order/archive/status?archive_id=BV1JHYd6GEKj
```

页面在输入框里敲字时自己会打这个，带 cookie 即可。两种返回：

```jsonc
// 是花火稿件
{"status":"success","result":{"auth_times":0,"renewal_times":0,"archive_info":{"cover":"...","title":"..."}}}
// 不是花火稿件（这一页永远授不了权）
{"status":"fail","error_code":500,"error_msg":"获取稿件信息失败：该稿件不是花火稿件"}
```

⚠ **这是这个类型最值钱的一条**：预检直接批量打它，几秒钟就能把
「哪些 bvid 在这一页根本授不了」标出来，不用开 N 次弹窗才发现。
2026-09-23 实测一份 39 条的蓝链清单，只有 **3 条**是花火稿件 ——
其余 36 条要走隔壁 tab「普通内容授权」，那是另一套表单（本配置类型不管）。

`auth_times` = 7 天内已申请次数，到 3 就没机会了，预检当 warning 提示、不拦。

## 三、没做的部分

- 选 30天 / 60天 / 90天 之后，下面会多出一排**只读**的日期区间（如 2026-09-23 至 2026-10-23），
  不用填，也不用管。
- **授权时间「自定义」** 不支持：选它那排日期区间变成可编辑的，没抓。
  要自定义日期请手工操作。
- **稿件avid** 不支持：清单统一用 bvid。
- **「普通内容授权」/「账号授权」两个 tab** 不在这个配置类型里。
