# 常规资源位批量开关 — 配置项抓取

抓取时间：2026-09-04（Chrome 152 / CDP 9222 挂已登录窗口）
对应配置：`config/forms/常规资源位批量开关.yaml`、`src/dl_filler.py`、`src/dl_runner.py`

---

## 一、页面

大会员投放系统「投放列表」，三个 Tab 各自一个路由（切 Tab 会换 URL，直接 goto 也行）：

| Tab | URL |
|---|---|
| 活动 | `https://rich-vip.bilibili.co/manage/v/delivery-manage/delivery-list/delivery/activity` |
| **单元** | `…/delivery-list/delivery/unit` |
| **创意** | `…/delivery-list/delivery/originality` |

前端 **Ant Design 5**：`css-mncuj7` / `css-var-«r26»` 这类编译哈希满页都是，**一个都不能用**。
能用的是语义 class（`.ant-table-row` / `.ant-form-item` / `.ant-pagination` / `.ant-dropdown` /
`.ant-modal-wrap`）+ 文字。

⚠ 全站规模：单元表 40604 条、创意表 128656 条。**不圈定范围就没法批量**，所以要么
填「活动ID」（整个活动筛出来），要么把范围切到「按清单」、给一串纯数字 ID
（那时逐个 ID 查，见 §三 末尾）。两个都不给会被挡下来。

## 二、表格

一张主表，判据：`thead th` 里同时含「单元ID」（或「创意ID」）和「操作」。
行 = `tbody tr.ant-table-row`，**`data-row-key` 就是这一行的 ID**（单元ID / 创意ID），
比按名称找靠谱得多 —— 名称会重（活动 708 里就有两行都叫「测试测试」）。

### 单元表列（19 列）

`（勾选框）| 单元ID | 单元名称 | 活动ID | 活动名称 | 活动类型 | 投放位置 | 单元状态 |
审核状态 | 流量分配ID | 流量分配比例 | 创意赛马 | 实验id | 实验分组id | 优先级 |
提交人 | 投放时间 | 频次限制 | 操作`

### 创意表列（13 列）

`（勾选框）| 创意ID | 单元ID | 单元名称 | 创意状态 | 审核状态 | 投放位置 | 活动名称 |
创意素材 | 创意泛化批次ID | 投放日期 | 提交人 | 操作`

⚠ **创意表没有「活动ID」列，筛选区也没有「活动ID」这一格** —— 只有活动名称。
这条决定了实现：层级=创意时先去单元表按活动ID查一遍，拿到 **活动名称 + 单元ID全集**，
再回创意表按活动名称筛，最后用单元ID全集把同名活动的行剔掉（`dl_runner._collect`）。

### 分页

表下方 `.ant-pagination`，默认 20 条/页，`.ant-pagination-options` 里能选
**10 / 20 / 50 / 100 条/页**。进页先拨到 100，翻页少一大截（实测 282 条从 15 页变 3 页）。

## 三、筛选区

`.ant-form-item`，label 文字在 `.ant-form-item-label` 里。**按 label 文字定位**，
别用 `input#act_id` 那种 id（是 antd Form 的 field name，改版就没了）。

单元表：单元ID、单元名称、**活动ID**、活动名称、活动类型、投放位置、单元状态、审核状态、
流量分配ID、是否有流量分配ID、创意赛马、实验id、实验分组id、优先级、投放流量池、提交人、投放时间

创意表：创意ID、单元ID、单元名称、创意状态、审核状态、投放位置、**活动名称**、
创意泛化批次ID、创意素材ID、创意类型、投放日期、提交人

按钮：「重 置」「查 询」（**中间有空格**，比对时先把空白去掉）。

⚠ **填值只能用 playwright 的 `fill()`（真键盘事件），不能用 JS 写 `.value`** ——
连「原生 setter + 派发 input 事件」那套也不行。antd 的 Form 是受控组件，值在它自己的
store 里：JS 塞进 DOM 的值**输入框里看得见**，点「查 询」带出去的却还是空条件，
查回来仍是全站四万条，**一句报错都没有**。

⚠ **「查 询」按钮也只能用真鼠标点**。JS 的 `el.click()` 点了没反应（不报错、表单不提交）。
所以 `dl_filler` 的做法是：JS 只负责按 label / 文字把目标**标记出来**
（`data-cc-field` / `data-cc-btn`），点和填交给 playwright。

⚠ 「单元ID」这一格**只吃一个 ID**，填 `41031,41030` 等于没筛（会回到全量 12 万条）。
  「创意ID」也一样。所以「不填活动ID、直接给一串 ID」只能**一个 ID 查一次**，
  `dl_runner._collect_by_id()` 就是干这个的。

## 四、状态与「更多」菜单 —— 这个配置类型的核心

状态选项（单元状态 / 创意状态，两边一样）：

    未开始 / 投放中 / 已完成 / 已暂停 / 已终止

操作列：`编辑` + `更多`。`更多` 是 **hover 触发**的 `.ant-dropdown`，
菜单项 `li.ant-dropdown-menu-item`，**内容跟着状态变**：

| 当前状态 | 单元「更多」 | 创意「更多」 |
|---|---|---|
| 投放中 | 查看详情 / 复制 / 复制全部 / **暂停投放** / 终止投放 / 查看数据 | 查看详情 / 查看数据 / 复制 / **暂停投放** / 终止投放 |
| 已暂停 | 查看详情 / 复制 / 复制全部 / **启动投放** / 终止投放 / 查看数据 | 查看详情 / 查看数据 / 复制 / **启动投放** / 终止投放 |
| 未开始 | 查看详情 / 复制 / 复制全部 / 查看数据 | 同左（**没有开关**） |
| 已完成 / 已终止 | 同上，没有开关 | 同上，没有开关 |

所以：

* 「开启」= 已暂停 → 点 **启动投放**
* 「关闭」= 投放中 → 点 **暂停投放**
* **未开始 / 已完成 / 已终止 三种状态后台压根没给开关**，只能跳过
  （未开始是投放时间还没到，要动得改投放时间，不在这个工具的范围里）

### ⚠ 「终止投放」不可逆

菜单里紧挨着开关的就是「终止投放」，点完状态变 **已终止**，之后菜单里**再也没有启动**。
`src/dl_filler.py` 里只认「启动投放 / 暂停投放」两个字符串，**永远不会点终止**，
而且点之前还会读一遍确认弹窗的文字、对不上就取消。别把这层校验删了。

### 二次确认弹窗（和价格策略那套不一样）

点完菜单项弹 `.ant-modal-wrap`（注意页面上留着好几个 `style="display:none"` 的空壳，
**只认可见的那个**，否则 playwright 的 locator 会撞上隐藏的然后一直等超时）：

| 层级 | 文案 |
|---|---|
| 单元 | `暂停投放  单元:【<单元名>】暂停后立即暂停全部投放，确定暂停单元？  取 消 / 确 定` |
| 单元 | `启动投放  单元:【<单元名>】启动后立即重启全部投放，确定启动单元？  取 消 / 确 定` |
| 创意 | `暂停投放  暂停后立即暂停全部投放，确定暂停该创意？  取 消 / 确 定` |
| 创意 | `启动投放  启动后立即重启全部投放，确定启动该创意？  取 消 / 确 定` |

确认后 toast：单元是「暂停成功」/「启动成功」，创意是「操作成功」。
**列表会自己重刷**，行留在原地、状态列翻过来 —— 所以判成功看状态列，别看 toast。

### ⚠ hover 拉菜单会拉空

表格刚重绘完那一下，第一次 hover 读回来的菜单是**空数组**，鼠标移开再 hover 一次就有了。
`dl_filler.menu_items()` 里「移开 → hover → 读」重试 4 轮就是为这个，别改成单次 hover。

### ⚠ 按状态筛的话，动完的行会从列表里消失

在「单元状态=投放中」的筛选下暂停一行，那一行立刻不满足筛选条件、列表刷新后就没了
（实测 20 条 → 19 条），页码也跟着变。所以工具**只按活动ID筛、不按状态筛**，
状态判断全在本地做。

## 五之二、台账（「本工具操作过的」这一档）

跑完一轮，成功翻转的那批会记进 `output/常规资源位开关台账.json`（`src/dl_ledger.py`）：
层级 + 活动ID + 方向 + 每条的 ID/名称。下次把范围切到「本工具操作过的」，
就按**反方向**取那批 —— 现在方向=开启，取的是上次被本工具**暂停**的那些。

「刚暂停完一批、过两天要原样恢复」是这个后台最常见的第二步，页面上没有任何地方
记得住这个清单（列表按状态筛出来的是**所有**已暂停的，包括别人暂停的），所以只能自己记。

⚠ 只记 `ok` 的行。跳过的（已是目标状态 / 未开始）和失败的根本没动过，记进去会让
「翻回去」翻到一堆本来就那样的行。

## 六、教训

1. **别按名称找行**，用 `data-row-key`（= ID）。这张表同名行是常态。
2. **别信 URL 参数**。点「查 询」之后 URL 会变成 `?unit_act_id=708&unit_state=1` 这样，
   但直接 goto 带参数的 URL **筛选条件不会生效**（创意表实测三种写法全部无效，
   回来还是 12 万条全量）。老老实实填表单点查询。
3. 「查 询」按钮的文字是「查 询」，中间有空格；比对前先 `replace(/\s+/g,'')`。
4. **表格出来了 ≠ 筛选表单能用了**。冷进页那几秒里，值填得进去、按钮点得动，
   但 antd Form 的 store 还没接上，条件带不出去 —— 查回来是全量，且**完全静默**。
   这条是这套页面最容易踩的坑：跑得越快越容易中。
   `dl_filler.query()` 的对策分两半：
   - **判据**：查完看条件有没有被推进地址栏（`?originality_id=134226`），
     而且要求**每个填的值都能在 URL 里找到** —— 只看有没有 `?` 的话，
     连着查好几个 ID 时会被上一次留下的参数骗过去。
   - **重试**：失败后**原地改值重查**，别重进页面。冷页正是失败的原因，
     重进等于每次都把自己送回冷启动（实测一个 ID 连着失败 4 次都有）。
     页面已经热了的时候（还在同一张表、上次填的也是同样这几格）连第一发都不会失败：
     一串 ID 逐个查，只有**第一个**会重试一次，后面全是一次过。
