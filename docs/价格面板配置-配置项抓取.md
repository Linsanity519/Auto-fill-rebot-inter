# 收银台价格面板 — 单元层配置项抓取

抓取来源：`manager.bilibili.co/v3/#/vip/resource-delivery/unit/edit/0`（**老系统**，prod），2026-08-24。
资源位：**收银台 → 收银台价格面板**，`position = 35`，`scene = 3`（收银台）。
（表格里名称严格等于「收银台价格面板」，不是「加更礼&结局点映收银台价格面板」也不是「签约面板」。）

同场景下另外几个价格面板位：加更礼&结局点映收银台价格面板 `87`、
加更礼&结局点映收银台价格面板（新) `94`、活动页价格面板 `90`、活动页价格面板新 `98`。

**两个好用的接口**（登录态下在页面里 `fetch` 就能取，比翻 DOM 省事）：

| 接口 | 给什么 |
|---|---|
| `/x/admin/vas/ads/position/list?pn=1&ps=100` | 全部资源位 ↔ position_id ↔ scene |
| `/x/admin/vas/ads/unit/config_materials?positions=35&panel_type=normal` | `pid_info_list`（729 条，每条带 pid / platform / product_type / pid_describe）、`origin_ids`(138) |
| `/x/admin/vas/ads/unit/list?position=35&...&pn=1&ps=20` | 这个资源位下已有的单元（共 1939 个），拿 unitId 去开创意页 |

⚠ `config_materials` 的 `panel_type` 就是页面上的「生效渠道」：`normal` = 全局、`direct` = 定向。
  **`direct` 下 `pid_info_list` 是空的** —— 定向那套不走 pid。

> ⚠ **这是老系统，不是 `资源位投放` 走的那套。**
> `config/forms/资源位投放.yaml` 的单元层跑在 `rich-vip.bilibili.co/delivery/unit/0`，
> 那边是 Formily（`.ant-formily-item`）。这里是 Vue SFC（`data-v-fba1d896`）+
> CSS-in-JS 编译类名（`tw-xxxxxx`）。**两套 DOM 完全不通用，选择器一个都不能抄。**

## 定位要点（踩坑清单）

1. **`tw-` 类名是编译哈希**（`tw-bywk2o` / `tw-6hmssk` / `tw-1m1sear`…），
   发版就会变，和 `价格配置.yaml` 里说的 `css-1a75fj6` 是一回事 —— **一律不要直接用**。
   稳定的定位方式是：**先按 `<label>` 的文字找到字段块**，再在块内按选项文字点。
   字段块的结构恒定是：
   ```
   <div>                       ← 字段块
     <label>字段名</label>       ← 第 1 个子节点，必是 label
     <div> …控件… </div>        ← 第 2 个子节点
   ```
   块内的每个选项也是 `<label><span><input type=radio|checkbox><span>选项文字`。
2. 必填标记在 label 的 class 里（多一个 `tw-1m1sear`），不是文本里的星号。
3. `<input>` 上带**真实 value**（`生效平台` 的 Android=9、`搭售类型` 的 award/zero…），
   校验时可以拿它兜底核对，但**点击要点外层 `<label>`**，直接 `input.click()` 有的不生效。
4. 页面**没有 Vue 实例挂在 DOM 上**（prod 构建，`__vue__` / `__vueParentComponent` 都没有），
   想读组件状态是不行的，只能读 DOM。
5. **资源位表格有 164 行**（各 tab 的行都在 DOM 里），按名称匹配时必须**取第一列严格相等**，
   否则「收银台价格面板」会同时命中「加更礼&结局点映收银台价格面板」。
6. 选中资源位**之后**「其他设置」这一整段才渲染出来。
7. **资源位表格比「单元名称」输入框晚出来**（它是另一次接口拉回来的）。
   拿输入框当「页面好了」的判据，十有八九会撞上「资源位表格里没有 xxx 这一行」——
   要单独等那一行出现。

## 交互上的坑（2026-08-24 实跑踩出来的）

这几条光看 DOM 看不出来，全是跑起来才发现的，改代码前务必先读：

1. **`placeholder` 写着「请输入…」的框，有的是纯下拉，有的是远程搜索 —— 两种混在一起。**
   判据是 **`input.readOnly` 当场的值**，不是 placeholder。但要注意它会变：

   | 控件 | readOnly | 怎么填 |
   |---|---|---|
   | `买赠商品` | 恒 true | 纯下拉，只能按文字挑 |
   | `商品ID` | **点开之前 true、点开之后 false** | 远程搜索：点开、打 id、**等几秒**才回来 |
   | `组合价格` 那两列 | 同上 | 同上 |
   | `价格面板pid` | false | vue-multiselect，打字过滤，也是远程的 |

   ⚠ 2026-08-26 订正：原来这里写「商品ID 是 readonly 的纯下拉、活动 708 下 0 条」，
   **是错的**。它是点开才变可编辑的远程搜索框，用合成 `click` 打不开这个状态，
   于是既没有选项也打不了字 —— 看起来就像「这个活动下没有商品」。实测 708 下
   打 `1223450133` 等 5 秒就出来了。所以这一族必须用**真实鼠标点击**打开
   （见 `pp_filler._open_input`），而且要等「**匹配上的那条**出现」，
   不能等「有选项了」（远程回来之前躺在浮层里的是上一轮的旧选项）。
2. **vue-multiselect 上的手势不统一，同一个页面里三种控件三个样**
   （`省份` / `sku选择` / `价格面板pid` 都是 vue-multiselect）：

   | 点什么 | 认哪个事件 |
   |---|---|
   | 标签上的 × （删已选） | **mousedown**，`click` 完全没反应 |
   | `sku选择` / `省份` 的选项 | **mousedown** |
   | `价格面板pid` 的选项 | **click**，`mousedown` 完全没反应 |

   两种一起发是不行的 —— 都认的话等于点两下，选上又取消。
   `pp_filler._vue_pick` 的做法是：先发 mousedown，**看选中状态变没变**，
   没变再发 click，还没变才报错。两种都不报错地失效，所以必须自己验。
   页面自己那套 `tw-` 控件（单选/复选/卡片上的 ×）倒是认普通 click。

2b. **`价格面板pid` 是多选，不是单选。** 一个 SKU 在每个平台上有各自的 pid，
   一个单元投几个平台就填几个（标签形如 `140(normal,android,连续包年,所有用户,233.00元)`）。
   当单选写的话每跑一次就往里**加**一个，越攒越多还看不出来。
3. **点 SKU 卡片、改 `sku选择`，会把「其他设置」里的面板级单选打回默认值。**
   实测 `赠单片` 被打回「默认」；拖拽不会。所以填写顺序必须是
   *先 sku选择 → 套餐排列 → 逐张卡片配搭售 → 最后才填 内容设置 / 选中类型 / 赠单片*。
   顺序反了的话最后全白填，**页面上还看不出来**。
4. **「面板个数」决定套餐排列分几段：N 段 = N-1 条分隔线。**

   | 面板个数 | 表头 | 分隔线 |
   |---|---|---|
   | 1个 | 无 | 0 条 |
   | 2个 | 面板1(推荐) / 面板2 | 1 条 |
   | 2个+查看更多 | 面板1(推荐) / 面板2 / 隐藏sku面板 | 2 条 |

   「1个」时**「面板1」「面板2」这两个 label 也不存在** —— 选中类型的那个套餐下拉
   直接挂在「选中类型」底下。按 label 找会报「找不到字段 面板1」，
   得按「块里第几个下拉」定位。

4b. **排序只能靠「把卡片拖到分隔线上」**。分隔线 `draggable=false` 拖不动，
   但可以当落点，卡片落到它**右边**。所以不能「按下标从左到右摆卡片、跳过
   分隔线的槽位」——那样卡片都到位了、分隔线还堆在原地
   （实测：想要 `[连,|,年,|,月]`，摆出来 `[连,年,|,|,月]`）。
   正确做法是**从最后一段往前铺**，每段的卡片倒序丢到「这一段前面那条分隔线」上，
   第 0 段再按下标摆。见 `pp_filler.arrange`。

4c. **拖拽是整页唯一用真实鼠标事件的地方，被浮层挡住会一声不吭地失效。**
   `sku选择` 选完之后它的下拉面板还开着，正好盖住套餐排列 —— 拖之前必须先收
   （`pp_filler.close_popups`）。
5. **`投放时间` 不会自动带出活动的起止时间**，除非 URL 里带了 `startTime` / `endTime`
   这两个 unix 时间戳。不带就是两个空框，而它是必填的。

### 2.3 套餐排列

DOM：

```html
<div class="panel-sort-wrapper">
  <div class="flex">                       <!-- 表头 -->
    <div class="panel-type-title">面板1(推荐)</div>
    <div style="width:42px"></div>
    <div class="panel-type-title">面板2</div>
  </div>
  <ul class="panel-sort-content flex">
    <div class="panel-type-item panel-type-item-active" draggable="true">
      <p class="panel-type-text">异形SKU</p>
      <div class="close-btn">…</div>        <!-- 点它 = 从 sku选择 里去掉这个 SKU -->
    </div>
    …
    <div class="panel-division" draggable="false"></div>   <!-- 面板1 / 面板2 的分界 -->
    …
  </ul>
</div>
```

要点：

- 卡片就是「sku选择」选中的那些，**顺序 = 面板上从左到右的展示顺序**。
- `.panel-division` 是**列表里的一个真实兄弟节点**，它前面的卡片属于面板1、后面的属于面板2。
  实测把卡片一个个删掉时分隔线会一路退到末尾（= 面板2 空了），
  所以**分界是数据，不是纯样式**。26 个 SKU 全选时后台给的默认是 13 / 13。
- 面板个数 = `1个` 时**没有表头也没有分隔线**（一条大列表）；
  = `2个+查看更多` 时表头变成「面板1(推荐) / 面板2 / 隐藏sku面板」。
- 排序和跨面板移动**只能拖**：卡片 `draggable="true"`，是 HTML5 原生拖放。
  分隔线本身 `draggable="false"`，不能拖分隔线。

### 2.4 每个 SKU 各自的搭售配置

点中某张卡片（`panel-type-item-active`）后，下面那几个字段就切换成**这张卡片的**配置。
也就是说：**选了 N 个 SKU，就要点 N 次卡片、各配一遍。**

**异形SKU**（特殊，没有「搭售类型」这一档）：

| 字段 | 必填 | 控件 |
|---|---|---|
| 价格面板pid | ✅ | 可搜索下拉 |
| 搭售商品 | ✅ | 文本，ph「请输入商品id」 |

**其余 25 个 SKU**：

| 搭售类型 | value | 展开出来要填什么 |
|---|---|---|
| 无 | `none`（默认） | — |
| 买赠 | `award` | 价格面板pid ✅ + 买赠商品 ✅（**两截，见下**）|
| 加价购 | `add` | 加购价格信息（加购价格 `+新增价格` + 组合价格）|
| 0元购 | `zero` | 0元购价格信息 → 组合价格 ✅ |
| 买赠+加价购 | `award+add` | 上面两套都要 |
| 买赠+0元购 | `award+zero` | 价格面板pid + 买赠商品 + 组合价格 |

**买赠商品是两截，不是一个商品ID**（这点当初抓漏了，跑起来才发现）：

| 字段 | 控件 | 取值 |
|---|---|---|
| 买赠商品 | readonly 下拉，9 选 1 | 观影券 / 会员天数 / 永久装扮 / 普通装扮 / 会员购抽奖机会 / 会员购运费券 / 会员购优惠券 / 会员购魔晶 / 道具 |
| 商品ID | readonly 下拉（**不是输入框**，尽管 ph 写着「请输入道具id」）| 选完上面那档才出现，选项形如 `1017391583097593239(联合会员：大会员x百度网盘月卡)` |

> ⚠ 2026-08-24 在「子凡测试25年」这个活动下实测，**9 个商品类型的「商品ID」下拉全是 0 条**。
> 浮层能打开，就是没有选项。所以「买赠」这条分支验到了「选商品类型」为止，
> 价格面板pid 也验过了（按生效平台填了 4 个），只有最后挑一个商品ID 没验成 ——
> 换个有买赠商品的活动再试一次。

**组合价格**（0元购 / 加价购 用）：一个 `增加组合价格` 按钮，每点一次加一行，
一行 = `请选择单会员价格pid` + `请选择加购商品id` + `删除`。
旁边还有两个按钮 `跳转配置会员价格` / `跳转配置加购商品`，是跳到别的后台页面的，别点。

```html
<button class="… add-combine-btn">增加组合价格</button>
```

### 2.5 价格面板pid 下拉的文本格式（做 pid ↔ SKU 映射的依据）

```
11439(normal,ipad,连续包年,人群包,148.00元)
        │      │       │        │       └ 价格
        │      │       │        └ 人群（所有用户 / 人群包）
        │      │       └ SKU
        │      └ 平台（android / iphone / ipad / pc / harmony / public）
        └ 类型（normal）
```

**下拉里的选项是按当前选中的 SKU 卡片过滤过的**，实测：

| 选中的卡片 | 下拉条数 | 下拉里出现的 SKU |
|---|---|---|
| 连续包年 | 181 | 连续包年 |
| 年度大会员 | 47 | 年度大会员 |
| 超大连续包年 | 178 | **连续包年**（⚠ 超大档位对应的 pid，SKU 字段写的还是「连续包年」）|
| 异形SKU | 226 | 不过滤，年度大会员/连续包年/连续包季/连续包月/季度大会员/月度大会员 混在一起 |

也就是说 **SKU 只能把 pid 收窄到一两百条，最终填哪个 pid 只能人来定**
—— 这正是要在机器人里维护一张「SKU（+平台/价位）→ pid」映射表的原因。

`买赠商品` 下拉是 `商品ID(名称)`，例如
`1017391583097593239(联合会员：大会员x百度网盘月卡)`、`948620797138806197(大会员年卡 × 美图秀秀季卡)`。

## 三、创意层（2026-08-25 初抓，2026-08-26 重抓订正）

⚠ **创意层不在老系统里**。单元保存后跳的是新系统：

```
https://rich-vip.bilibili.co/delivery/creativity?unitId=<单元ID>&position=35
```

老后台那个 `manager.bilibili.co/v3/#/vip/resource-delivery/originality/detail?...`
会 302 到 `rich-vip.bilibili.co/manage/v/big-vip/delivery/creativity?...`，
**但那个带 `/manage/v/big-vip` 前缀的地址只渲染外壳、内容是空的**，
要用上面那个不带前缀的直连地址。

⚠ 这是**第四套 DOM**：class 前缀 `arco-`（Arco Design），外层「创意1/创意2」标签页是 antd。
和单元层（tw-）、资源位投放新系统（Formily/mega-ant-）、价格配置（antd）都不一样，选择器一个都不能抄。

⚠ **直连地址打开时，已存创意的内容不回填**。实测单元 40900 已有创意 137896、40817 已有 3 条，
页面照样是空表单（只有下面说的那几个只读回显有值）。要读已经配了什么，走接口：

```
/x/admin/vas/ads/originality/v3/by_unitid?unit_id=<单元ID>
```

它同时给两样东西：`templatev3[0].form_config`（单元层传过来的 panel_list / sale_strategy /
add_type / grant_type / bundle_id / combine_price）和 `originalitys[].properties`
（一张扁平表，`key` = 「<cashier>:<字段>」）。**这就是「单元配置 → 创意配置」的接缝**。

### 3.1 页面形态：套餐排列是一条「只读的 SKU 卡片条」

```
上传创意素材
  [创意1] [创意2] …          ← antd Tabs，底部「新增创意」加一条
    套餐排列  *              ← 只读，把单元层排好的 SKU 按面板列成一排卡片
      面板1(推荐) [连续包年][超大连续包年][连续包月]… ｜ 面板2 [年度大会员][季度大会员]…
    ── 点中的那张卡片的字段 ──   ← ⚠ 同一时刻只显示一张卡的字段
    价格面板切换按钮 *         面板1: / 面板2: 两个 text（只有两个面板时才有）
  [关 闭] [保 存]
```

⚠ 初抓时把「所有 SKU 的字段竖着排成一长列」记错了。真实情况是：12 个 SKU 的字段组**都在
DOM 里**，但只有选中那张卡的一组是可见的，其余 `display:none`（实测 38 个 input：
12×3 + 2，其中 36 个不可见）。**点卡片才切换**，所以选了 N 个 SKU 就要点 N 次、配 N 遍。

卡片有哪些、怎么分面板，来自单元层 `price_panels`：
`show=0` 表示这个 SKU 被选中并展示，`show=1` 表示没选中（⚠ 和字面意思相反）；
`group=1` 落面板1、`group=2` 落面板2。

### 3.2 ★ 字段完全由「这个 SKU 的搭售类型」决定

创意层没有「配置类型」这种总开关 —— 同一条创意里，A 套餐是「买赠」就多 6 个要填的字段，
B 套餐是「无」就只有 2 个。

⚠ 单元层那个「搭售类型」单选，在数据里是**两个字段拼出来的**：
`sale_strategy`（`none` / `award`=买赠）和 `add_type`（空 / `zero`=0元购 / `add`=加价购）。

| 搭售类型 | 创意层字段（\* = 必填） |
|---|---|
| **无** | sku角标文案、sku红包弹窗动画 —— 就这两个 |
| **买赠** | ＋ 买赠商品\*、商品ID\*（都是只读回显）、配置类型\*、商品权益名称\*、支付成功商品图(327\*327)\*、权益跳转链接\*；<br>配置类型=icon+文案 → 再多 小灰条文案\*、icon(0~240\*60)；<br>配置类型=图片 → 再多 icon(327\*327)\*，且角标文案提示语从「1~6字」变成「1~10字」 |
| **0元购** | ＋ 加购商品id\*（只读回显，一个 pid 一行）—— 只加这一个 |
| **买赠+0元购** | 两组叠加。线上最常见，样本 40900/40817/40773 的「连续包年」都是这档 |

两张特殊卡：

| SKU | 独有字段 |
|---|---|
| 异形SKU | 搭售商品（只读回显）、SKU底图(654×414)。**这张卡没有「搭售类型」这一档**，也就没有上面那两组 |
| 升级超大 | 升级时长\*（≥1，单位「月」）、角标文案（**4~8 字**，不填走默认，这一行没有独立 label）、默认选中。它照样能配买赠/0元购 |
