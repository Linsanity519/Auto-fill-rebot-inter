# 开发规范

## D01：每次迭代的最小闭环

读 AGENTS 和相关契约 → 确认实际调用链与现状 → 明确业务结果 → 按层实现最小改动 → 验证正常与相关失败路径 → 更新契约/说明 → 报告实际结果。

任务中出现新约束时更新同一方案。不得只实现容易的入口而让桌面、CLI、MCP 语义分叉。规划属于设计，落地属于实现，验证属于证据，交付时分别说明。

## D02：代码

- 新 Python 代码带明确输入输出类型；公共业务契约使用 dataclass、Enum、Protocol 或有明确用途的 schema，避免不受约束的 dict 穿透所有层。
- 金额与比例声明单位和精度；涉及金额计算使用 Decimal 等明确精度方案。时间说明时区；业务时钟通过依赖传入，使测试可重现。
- 函数与模块围绕单一职责，出现多种变化原因时拆分。长度是评审信号，不为满足行数硬拆。
- 中文说明业务含义，标识符表达具体意图；注释解释规则来源、兼容原因和不明显的边界，避免重复代码。
- 异常在适当边界转换成有代码、阶段、对象、可重试性与可读说明的结果。不得把未知失败吞成空列表、False 或成功。
- 副作用操作具备明确超时、取消点和结果查询；“请求超时”与“平台未执行”不得混为一谈。
- Page、数据库连接等资源有明确持有者与关闭范围。附加到用户会话不表示可以关闭所有用户标签页。
- 不新增核心层动态导入、反射调用 I/O 或全局可变任务状态。

## D03：界面与 AI

字段的业务定义统一；界面可做即时提示，最终校验在业务用例。模板、桌面、CLI 和 MCP 共同使用规范化输入。AI 缺信息时返回具体缺失字段、允许值和下一步，不能猜账号、范围和目标状态。

确认页包含环境、账号、对象、变更前后、跳过与影响范围；修改输入使旧计划失效。中文摘要由结构化计划生成。普通客户端有文字回退，MCP Apps 是可选增强。

界面验证长内容、窄/矮窗口、加载失败、重复点击与空结果。保留滚动、关闭和错误反馈，不以移除提示消除报错。

## D04：验证矩阵

| 改动 | 必要验证 |
|---|---|
| 纯文档 | 静态检查、相对链接与事实核对 |
| 领域规则 | 正常、边界、非法输入，使用确定性数据 |
| 应用编排/任务状态 | 缺输入、计划变化、重复调用、部分成功、未知结果与恢复中的相关场景 |
| API/浏览器适配 | 脱敏响应/页面夹具；必要时在获授权环境核验，记录未实测边界 |
| SQLite/档案 | 升级、失败恢复、重复导入、冲突与附件缺失中的相关场景 |
| GUI/MCP/CLI | 相同输入共享结果语义，错误可理解，入口不绕过用例 |
| 构建/发版 | 完整离线检查、安装与升级兼容、打包后的启动检查 |

先复现问题再验证修复。测试关注外部可观察结果和规则，不为机械证明自己写了某行代码而加测试。不为低影响文案/样式修改建无价值测试。

执行 `python tools/check_project.py` 获取统一结果。四项需要网络/浏览器/更新进程的旧测试被明确列出，不计入离线通过。新 unittest 测试放 tests 下具备 __init__.py 的子包；新增 tools/test_*.py 必须登记到离线清单或说明环境要求。

不连接真实内网验证单元测试，不使用真实凭据和业务档案当仓库夹具。离线检查的阻断机制只避免意外联网，不是恶意代码的安全隔离。

## D05：数据、依赖与发版

- 保留用户文件；清理仅针对已确认的构建产物。新数据路径必须通过统一路径/仓储边界。
- 不把 cookie、令牌或完整业务档案加入仓库/日志/公共统计；现有历史例外不是新增硬编码凭据的许可。
- 新增依赖须说明用途与现有库不能满足之处，并记录经验证的版本；运行依赖变化同步 requirements 与 RUNTIME_ID，评估完整安装包迁移。
- 当前 requirements 使用下限约束，尚未完成完整依赖锁定。这是已登记的存量债务，不得声称构建已完全可重现；未来版本锁定需连同目标 Windows/Python 环境验证。
- 不随意更新版本号、打标签或发布。发版必须具备准确 CHANGELOG、版本/运行时代号、完整检查和升级兼容证据。
- 不能用 continue-on-error、跳过脚本或降低断言把失败变绿。真实不适用的测试说明原因；业务变更导致预期变化时更新与其对应的测试。

## D06：交付说明

对使用者说明行为变化；对维护者说明涉及层、验证命令/结果、兼容性与剩余限制。必要时附任务或 ADR 链接。未执行的在线检查、云端 CI 和安装包测试必须明确标记未执行。
