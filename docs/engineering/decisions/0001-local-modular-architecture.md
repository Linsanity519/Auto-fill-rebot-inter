# ADR-0001：本地模块化应用与增量架构约束

- 状态：已采用，业务迁移尚未实施
- 日期：2026-10-04
- 依据：维护者在本次设计对话中要求领域/编排/前端/存储分层、AI 接入、完整数据归集及强制开发规范；同时明确个人维护且没有内部服务器资源。

## 决策

保留 Python 与桌面入口，新增 domain/application/adapters/entrypoints 和 bootstrap 的职责边界。为兼容现有更新包，运行模块继续置于 src 下。本地 SQLite 与完整档案归集按业务切片落地，MCP 复用同一用例。

存量文件登记精确清单，允许修复；新增模块执行静态分层检查。CI 与本地构建运行统一质量检查，不以迁移所有旧模块作为第一步。

## 备选

- 全量重写：风险与维护成本过高，现有页面经验难以一次重建。
- 只写提示词规范：不能自动识别常见架构退化。
- 多服务集中部署：超出当前资源条件。

## 边界

自动检查覆盖静态结构，不证明业务正确或无法被人为绕过。合并强制检查依赖 GitHub 仓库规则；本地配置文件不会自动启用远端保护。完整依赖锁定、旧代码全部合规、真实平台回归均仍需后续工作。
