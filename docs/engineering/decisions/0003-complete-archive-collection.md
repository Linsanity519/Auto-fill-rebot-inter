# ADR-0003：复用智能表格，完整档案单独验收

- 状态：本地档案与归集组件已实现；线上字段、容量、读取授权待核实
- 日期：2026-10-04

## 已确认事实

Git 源码未包含生成文件 src/_bundled.py；v1.1.24 实际发布 ZIP 内有非空 SHEET_WEBHOOK。构建从 Actions 的 USAGE_SHEET_WEBHOOK_URL 注入，现有 report.sheet_webhook_url 统一解析。密钥值与含值的 ZIP 不提交到仓库，写入凭据不当成收集端读取/管理凭据。

原统计链路只发送概要，其拒收降级与公开 team.json 不适合保存完整档案。旧摘要继续工作，完整档案有自己的字段映射、outbox 与接收核验状态。

## 档案与传输

版本化 ZIP 包含输入、计划、确认、条目结果、事件和内容寻址附件。SHA-256 校验每个附件及整个包；重复接收去重，同一 ID 不同内容进入冲突表。导入不执行文件、不创建写任务，拒绝路径穿越、重复文件、未声明文件、附件缺失和超限解压。

旧执行器标记 legacy_snapshot：保存完整输入、表单配置、业务选项、日志、结果及本轮截图/结果文件，不伪称已有逐步骤平台证据。旧 manifest 导入标记 legacy_partial，缺失历史无法补造。

完整包编码成可校验分块，使用同一表格的专用字段或经核实的明细入口。一次发送一块，拒收或超时保留重试；收集端按档案和分块编号去重。附件上传实际内容，不用本机路径冒充已回收。

pending/retry/rejected 表示尚需处理；accepted 仅是接口接收。收集端重组、校验全部附件并返回匹配回执后才标为 verified_complete。回执属于维护者工作流，不提供外部身份签名保证。

## 自动化与阻塞

客户端启动/完成后补传；未核实字段时仍保存本机档案与队列，并显示配置未完成。手动导入是补交和备份，不替换日常自动回传目标。

维护者的 tools/collect_archives.py 复用已有 wecom-cli 读取授权和经验证的分页 SQL，也支持本地 JSON 导出联调。超过页数上限或游标异常必须失败；此工具不写 team.json、不推 GitHub，档案目录不应位于公共仓库。

本次浏览器工具的站点安全策略拒绝读取用户提供的企业微信表格；未尝试绕过。实际列 ID、类型、容量与收集端授权尚缺，不能证明原表能接收全部内容。archive_collection.enabled 和 schema_verified 默认关闭。两端真实收齐附件前，M3 线上验收未完成；自动回执返回通道也待权限核实，当前支持文件回执。

64 MiB 是本机档案解压限制，不是对表格容量的承诺。大文件通道与长期留存需根据真实限制决定，必要时接入已有受控文件存储并保持同一校验契约。

## 验证

两个隔离数据目录、附件字节一致性、乱序/重复分块、缺块、冲突、拒收、超时以及接收/完整状态区分均有离线测试，未向真实表格发送内容。
