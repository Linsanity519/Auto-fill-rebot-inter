# 业务、数据与 AI 接口契约

这是后续业务迁移的验收规范，不宣称这些契约已经在所有旧功能实现。

## C01：功能契约

每个新增/迁移功能声明 capability_id、schema_version、中文名称/用途、前置条件、字段规范、动态选项查询、执行副作用与结果结构。

字段说明包含类型、必填、单位、格式、范围、示例和条件依赖。真实账号/环境/对象 ID 来自查询或明确输入，不由模型编造。UI 布局提示与业务字段分开；不在三个入口复制业务规则。

## C02：计划

Plan 至少含 plan_id、capability/schema/rule 版本、账号与环境、规范化输入快照、稳定 item_id、对象 ID、before/after、action、跳过原因、影响范围及有效性条件。

prepare 可以做已声明的只读查询，不能暗中创建中间对象。若必须写入才可演练，应标为实际操作并进入授权与档案流程，不叫 dry-run。

执行引用已保存的计划，不能允许调用方用同一 plan_id 替换参数。确认绑定计划版本/摘要、账号、范围；平台状态变化时重新核验。可信 UI 或可验证的预授权规则提供授权，模型自述不是授权凭证。

## C03：执行与结果

任务、项目、步骤均有稳定 ID，行号只作展示。持久状态表达 prepared、awaiting_confirmation、running、submitted、verified_success、verified_failure、unknown、cancelled、skipped 等实际需要的阶段，不靠一串日志猜状态。

相同输入和相同目标状态不自动意味着操作幂等。平台有幂等契约时按契约使用；否则提交后回读对象状态/ID。失联、超时、写盘失败应保留未知事实，不能盲目重提。

结构化结果包含业务状态、对象、阶段、错误代码、是否可重试、证据引用、下一步。transport 成功、HTTP 200、工具调用完成均不等于业务生效。批量操作逐项呈现已完成、失败、跳过和未知。

长任务返回 job_id 之后必须有实际宿主持有任务；若客户端退出会终止执行，产品必须明确展示这一点。取消不能自动撤销已完成的外部提交。

## C04：本地数据与完整归集

任务档案包含输入、计划、采用的规则版本、确认、操作事件、结果与所需附件。区分发起者、AI/桌面入口、执行设备、实际平台身份；无法验证的身份标记为声明。

execution_status 与 collection_status 分开。导出不等于接收，接收不等于任务成功。归集事件有稳定 ID、顺序、来源和时间；相同事件去重，冲突不得无声覆盖。

档案附件使用包内路径和校验值，导入不执行文件。SQLite 迁移和备份保持一致性；完整档案进入受控的业务档案位置，不复用公开统计快照分发。

## C05：迁移验收

首次迁移一项功能需证明：三个入口共用用例；缺参不执行；预检无业务写入；同一资源互斥；计划变更使原确认失效；提交未知可核验；业务结果与归集状态可分别查询。

使用代表性样例验证 AI 工具说明，不宣称 schema/Skill 能保证所有模型正确理解。协议元数据只是描述，服务端业务校验仍需执行。
