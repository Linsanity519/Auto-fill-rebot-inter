# DMP 人群延期 — 页面结构抓取

抓取来源：`bangumi-mng.bilibili.co/marin/s/full-ogv-data/user-assets/crowd-manage/crowd-list`（prod），2026-08-12 ~ 08-13 在真实页面上逐项验证。

对应配置：[config/forms/DMP延期.yaml](../config/forms/DMP延期.yaml)　执行器：[src/dmp_runner.py](../src/dmp_runner.py)

---

## 一、最容易踩的三个坑

### 1. antd 的 class 前缀是 `full_ogv_data_antd-`，不是 `ant-`

这套页面是带前缀打包的 antd。照抄通用写法（`.ant-picker-cell`、`.ant-pagination-next`）**全部落空**。

### 2. 双字按钮中间是全角空格

页面上渲染出来是「操 作」「保 存」「取 消」「搜 索」。`get_by_text(..., exact=True)` 匹配不到，`\s` 也匹配不到那个空格（U+2005 / U+3000）。程序统一先把空白剔干净再比。

### 3. 列表会异步重渲染，**任何按下标的定位都不能用**

`rows.nth(i)` 拿到下标后再去点，中间只要刷新一次，下标 `i` 指向的就是**另一个人群** —— 轻则「元素不可见」超时，重则**在错误的人群上执行延期**。

规避方式：
- 定位某一行 → 按 `data-row-key` 拼选择器，Playwright 每次动作重新解析
- 读整张表 → 一次 `evaluate_all` 原子取回，不要 count() + 逐个 nth()

## 二、列表页

### 表格列（0 起）

| # | 列名 | 说明 |
|---|---|---|
| 0 | （勾选框） | |
| 1 | 人群ID | 和 `data-row-key` 相同 |
| 2 | 人群名称 | |
| 3 | 覆盖人数 | 带千分位，如 `329,941` |
| 4 | 人群类型 | 自定义人群 等 |
| 5 | 人群状态 | 生效中 / 已失效 / … |
| 6 | 推广状态 | |
| 7 | 人群包更新时间 | |
| 8 | **失效时间** | 延期改的就是这一列 |
| 9 | 更新人 | 如 `linzifan01` |
| 10 | 人群设置 | |
| 11 | 操作 | |

> ⚠ `tbody` 第一行是 antd 的测量行（12 个空 td、无 `data-row-key`），必须用
> `tbody tr[data-row-key]` 排掉，否则会被当成一条人群。

### 归属筛选

顶部是 antd Radio 组：`全部 / 我创建的 / 分享给我的`，点 `label[class*=radio-wrapper]`。
选中状态立刻变，但**列表要 3 秒以上才重渲染** —— 先等 class 出现 `-checked` 确认点中，再等列表。

### 搜索

- 输入框 placeholder：`请输入人群名称或人群ID`
- 后端接口：`GET /dmp/admin/crowd/list/page?pageNum=1&pageSize=10&id_or_name=<关键词>`
- 按人群ID搜只返回 1 条

> ⚠ **判断搜索是否生效，不能只看「列表不再变化」**：搜索响应回来之前，
> 搜索前的那一屏本来就是静止的，一判就过。后果是要么拿到旧列表里同 ID 的行，
> 要么因为目标不在旧列表里就误判成「这个人群不存在」（排在第 3 页的人群必然中招）。
> 判据必须是「这一屏每一行都对得上这个关键词」。

### 分页

- 21 页（全部）/ 10 页（我创建的），10 条/页
- 下一页：`li.full_ogv_data_antd-pagination-next`，**点 li 没反应，要点它里面的 button**
- 翻页后同样要等到「第一行的 key 变了」才算成功

## 三、操作菜单

`操作` 列是 antd **Dropdown.Button**：左边「操 作」是主按钮（点它没用），右边省略号才是菜单触发器，**hover 展开，不是 click**。

```
button.full_ogv_data_antd-dropdown-trigger   ← 触发器（省略号）
li.full_ogv_data_antd-dropdown-menu-item     ← 菜单项
```

> ⚠ 鼠标如果已经停在触发器上（上一条刚点过同一位置），再 hover 同一坐标
> **不会触发 mouseover**，菜单永远不展开。每次要先把鼠标挪到角落再 hover。

菜单项随人群状态变：

| 状态 | 菜单项 |
|---|---|
| 生效中（8 项） | 查看 / 删除 / 更新 / 共享 / 人群导出 / 重试推广 / 人群缩放 / **人群延期** |
| 已失效（6 项） | 查看 / 删除 / 更新 / 共享 / 人群导出 / 重试推广 |

**已失效的人群没有「人群延期」，系统层面就延不了。**

## 四、延期弹窗

```
标题：有效期更改
      人群名称：<名称>
      人群有效期至：[日期选择器]
      取 消    保 存
```

- **没有「确认」这一步**，选完日期直接保存（`confirm_texts` 配成空）
- 日期输入框是 `readOnly`，只能点面板选，填不进去

### 日期面板

- 可选格子：`td.full_ogv_data_antd-picker-cell-in-view:not(.full_ogv_data_antd-picker-cell-disabled)`
- 格子的 `title` 属性就是 `2026-08-13` 这种标准日期，直接拿来用
- 月份标题：`.full_ogv_data_antd-picker-header-view`（`2026年8月`）
- 翻月：`button.full_ogv_data_antd-picker-header-next-btn` / `-prev-btn`

**可选范围 = 明天 起 到 今天+180天 止**，跨 6 个月面板。实测 2026-08-12 当天上限是 2027-02-08，次日变成 2027-02-09 —— 上限每天往后挪。

> ⚠ 三个必须注意的点：
> 1. **只看当前月会拿到「本月最后一天」**，比真正的上限早好几个月。必须一个月一个月往后翻。
> 2. **判断面板开没开，只能看浮层容器**（`.full_ogv_data_antd-picker-dropdown` 不带 `-hidden`）。
>    不能拿「有没有可选格子」当判据 —— 翻到可选范围之外的月份时，面板开着却一个可选格子都没有，
>    会被误判成关着，再点一次输入框就真关了。
> 3. **翻月找完上限，要把面板翻回起始月**。停在「全是禁用」的月份上，下次再算就从空月份起步，
>    直接得出「没有任何可选日期」。

上限对一次批量运行里的所有人群都一样，所以程序只在第一个人群身上翻一次，之后复用（省掉每个人群 6 次翻月）。

## 五、性能参考

实测单个人群约 7 秒（不含 5 秒冷却）：hover 展开菜单 1.5s + 弹窗 1.5s + 开面板 0.8s + 选日期 0.5s + 保存 2s。

第一个人群多花约 15 秒用于翻月确认当天上限。
