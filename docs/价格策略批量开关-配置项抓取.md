# 价格策略批量开关 — 配置项抓取

抓取来源：`rich-vip.bilibili.co/manage/v/experiment-manage/strategy-center/list/edit/<数字ID>`
（新系统，prod），2026-08-28 实地点出来的。
这就是 `价格配置` 那个配置类型「新建」弹窗所在的策略编辑页 —— 本功能操作的是**同一页底部那张「价格配置」表**，只点每行的「开启 / 关闭」，不开弹窗。

- 前端栈：**Ant Design + ProComponents**（和 `价格配置.yaml` 说的一致）。
- 编译哈希类名满页都是：`css-1a75fj6`、`css-var-«ra1»` / `«ra1»` 这种。
  **一个都不能用**（和 `价格配置.yaml` 顶部那条警告同源）。定位一律靠：
  语义 class（`ant-table-row` / `ant-dropdown-menu-item` / `ant-pagination-*`）+ 文字。

## 二、行 & 关键单元格

- 行：`table tbody tr.ant-table-row`
  - 带 `data-row-key="<uuid>"`（服务端记录ID）。**会话内稳定**，但整页重新拉数据后不保证不变 ——
    **匹配用「人群名称」文字**（`td:first-child`），别依赖 row-key。
- 「人群名称」= 第 1 个 `<td>`。可能重名（页面不拦），需要兜底时再取「优先级」列。
- 「人群选组」= 第 2 个 `<td>`：`不限` / `ogv dmp人群包` / `基本人群(实时数据)` …
  ⚠ **`人群选组 = 不限` 的行不能开启**（业务规则，运营明确说的；页面本身不拦、「开启」链接照样在）。
  批量开启时这类行要**跳过并说明原因**。
- 「状态」列文字：见下。
- 「操作」列 = 最后一个 `<td>`，内部固定是：

```html
<div style="display:flex;align-items:center;justify-content:flex-start;gap:8px;">
  <a>开启</a>                          <!-- 或 <a>关闭</a>，纯 <a>，没有 class、没有 href -->
  <a class="ant-dropdown-trigger">更多</a>
</div>
```

## 三、开启 / 关闭 —— 一键直接生效，**没有二次确认**

实测（2026-08-28，`测试-连续包月-B` 这行）：

| 起始状态 | 点「操作」列的 `<a>` | 结果 |
|---|---|---|
| 状态`未开启`，链接文字`开启` | 点 `开启` | 状态→`已开启`，链接→`关闭`。**没有弹窗、没有 Popconfirm、没有 Modal** |
| 状态`已开启`，链接文字`关闭` | 点 `关闭` | 状态→`已关闭`，链接→`开启`。同样没有任何确认 |

- 变更是**异步**的：点完立刻读还是旧值，约 1~2 秒后行内文字原地更新（表格不整体重刷）。
  判据用 `wait_until`：链接文字从`开启`翻成`关闭`（或反之）/ 状态列文字变化。
- 没捕捉到 toast（`.ant-message-notice` 一直是空，可能太快）。别拿 toast 当成功判据，看行内文字。
- 普通 Playwright `.click()` 就能点动，不需要真实鼠标事件。

### 状态列有三个值，别只认两个

| 状态文字 | 含义 | 「操作」列链接文字 |
|---|---|---|
| `未开启` | 从没开过 | `开启` |
| `已开启` | 开着 | `关闭` |
| `已关闭` | 开过又关了（**不会退回`未开启`**）| `开启` |

→ **方向判断以链接文字为准**（只有`开启`/`关闭`两种），比状态列（三种）省事：
- 目标 = 开启：链接是`开启`的行才点（覆盖 `未开启` + `已关闭`）
- 目标 = 关闭：链接是`关闭`的行才点（只有 `已开启`）
- 已在目标态的行：跳过

`<a class="ant-dropdown-trigger">更多</a>` 点开 → `.ant-dropdown:not(.ant-dropdown-hidden) .ant-dropdown-menu-item`：

编辑    查看    白名单    删除

## 五、翻页

「价格配置」表自带 antd 分页：
`ul.ant-pagination.ant-pagination-mini.ant-table-pagination`，
含 `li.ant-pagination-total-text`「第 1-4 条/总共 4 条」。

- 抓取时只有 3~4 行，没出现页码。antd 默认页大小 **10**。
- `已关闭` 的行再点 `开启` 能正常回到 `已开启`（已验，2026-08-28）。
- 行数 > 10 时要逐页处理：`.ant-pagination-next:not(.ant-pagination-disabled)` 点下一页，
  或（更稳）点 `.ant-pagination-total-text` 拿总数、用 `li.ant-pagination-item` 逐页跳。
- 每翻一页等 `tbody` 重新渲染（行的 `data-row-key` 变）再读。
- 也可以考虑把 pageSize 调大（页脚若有「N 条/页」选择器），一次读完 —— 待定，抓取时行太少没验证。

## 六、跨策略

- 每条策略一个编辑页，URL 尾巴是**数字ID**（本次实测 `.../list/edit/186`），
  和页面上显示的「策略id: 0713...9440」那串**不是一回事**（后者是业务ID，前者是路由ID）。
- 「当前打开的策略页」：不导航，直接读当前页那张表。
- 「指定多条策略」：需要**路由数字ID**才能 `goto`。业务ID → 路由ID 的换算还没抓
  （大概率要走策略列表页 `.../strategy-center/list` 或它的列表接口）。
  ⚠ 台账记忆里应存**路由数字ID + 策略名称**，别只存业务ID，否则跳不过去。

## 六之二、已落地的实现（2026-08-28）

mode `pt_toggle`，**一个**配置类型 `价格策略批量开关`，界面上一个 segmented 切
开启 / 关闭方向（不是两个独立类型 —— 那样侧栏会多两项）。

| 文件 | 干什么 |
|---|---|
| `config/forms/价格策略批量开关.yaml` | name/nav/mode/toggle/ledger/scopes/ui（`direction` 只给命令行兜底） |
| `src/pt_filler.py` | `snapshot()` 一次 evaluate 读整页行；`toggle(name, dir)` 点 `<a>` 并轮询文字翻转；`open_strategy(route_id)` 跳编辑页；`next_page()`/`first_page()`（JS 定位到价格表自己的分页条，避开另一张表） |
| `src/pt_strategy.py` | `classify()` 认 URL/路由ID/业务ID；`StrategyResolver` 扫策略列表页把业务ID→路由ID |
| `src/pt_runner.py` | preview（解析策略清单、逐策略开表、按范围筛、逐行分类）+ run（按策略分组、逐页、逐条确认、写 csv） |
| `src/pt_ledger.py` | `output/价格策略开关台账.json`；`names_for(since=)`、`strategies()`（台账里出现过的策略，新→旧） |
| `src/runner.py` `_flush_ledger()` | `价格配置` 跑完把成功的人群名 + 路由ID 追加进台账（yaml 写了 `ledger:` 才做） |
| `src/registry.py` `MODES["pt_toggle"]` / `src/formcfg.py` `BY_MODE["pt_toggle"]` | 接线 |
| `src/webapp.py` `_caps` 加 `toggle`、`load_and_check` 传 `toggle_direction/pt_scope/toggle_params/toggle_strategies`；`assets/webui/*` 方向 segmented + 两个文本框 | 界面 |

**方向**：`toggle_direction` = on/off（界面切）。
**范围**（scopes）：`keyword`（子串命中人群名称，留空=整页）/ `ledger`（读台账按策略筛）/ `all`。
**策略**：`toggle_strategies` 文本框，留空=当前页；填了=逐条 goto；留空且范围=ledger → 台账里所有策略。
`已在目标态` 的行 → 核对页标 done；`人群选组=不限` 且方向=开启 → 标 issue、不执行。

## 七之二、策略列表页（跨策略要用，2026-08-28 抓）

`.../strategy-center/list` —— 就是「新建策略」和进各策略编辑页的入口。

- 一张 antd 表，`thead`：`策略id / 策略名称 / 策略场景 / 资源位 / 投放时间 / 策略类型 /
  目标类型 / 模型名称 / 生效流量 / 策略状态 / 提交人 / 优先级 / 修改时间 / 操作`。
- **`tr.ant-table-row` 的 `data-row-key` 就是路由数字ID**（实测 rowKey `192` ↔ 策略id
  `26011902989580`）。`td[1]` 是**业务ID**（页面上到处显示的那串 14 位）。
  → 业务ID → 路由ID 的换算 = 读这张表，`{td[1]: data-row-key}`。
- 「操作」列的「编辑」是 `<a>` 但 `href` 为 null（JS 跳转）。所以进编辑页只能自己拼
  URL：`.../strategy-center/list/edit/<data-row-key>`，和 §六 那个 `edit/186` 一个样。
- 分页：`第 1-20 条/总共 192 条`，20/页 → 10 页；有「N 条/页」选择器（`.ant-pagination-options`）。
- 搜索区：`策略id` 输入框 + `策略名称` 输入框 + `查 询` / `重 置`。本工具没用它，
  直接扫 10 页把 `{业务ID: (路由ID, 名称)}` 全读回来（192 条，够快）。见 `src/pt_strategy.py`。
- 没抓到能直接取数的接口（列表数据的 XHR 在监听挂上之前就发完了）。

## 七、还没抓 / 待验

- **⚠ 冷跳转策略编辑页读不到「价格配置」表**（2026-08-28 实测）：`page.goto(.../list/edit/186)`
  之后表头能出来、行一直是 0，也不发 `ads` 请求，等 36 秒都没用；页面上「策略名称」
  也是空的（说明这条策略的数据 fetch 没被触发）。用户从列表页点「编辑」进去是好的。
  → 说明这张 SPA 的价格配置列表是被「从列表页带过来的路由状态 / 某个交互」触发拉取的，
    单靠 URL 深链不行。**跨策略 `open_strategy` 因此是尽力而为**：等不到就抛明确提示，
    让用户手动打开那条策略页、用「当前打开的策略页」。要修的话得走「goto 列表页 →
    翻页/搜到那一行 → 点『编辑』<a>」这条路（href 为 null，只能 JS click）。
- 价格配置表行数 > 10 时的翻页实际行为、页脚有没有 pageSize 选择器（抓取时只有 3 行）。
- 连续快速点多行有没有节流 / 报错（批量时要不要每行之间 settle 一下）。
- 开关失败时页面怎么表现（没遇到过失败）。
